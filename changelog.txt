Updated  Machine Control and Audio Setup.

Machine Control:

Now uses a single DRO frame above the motion controls.
An optional MCS row can be shown alongside the normal WCS row, with a toggle
to enable / dissable in app settings.

Updated the machine motion and command controls. Two motion-control layouts can
be toggled in Settings: the default layout gives direct per-axis step-size
access for Phi, Radius, and Height, while the alternative layout uses simpler
direction buttons with a global step-size selection.

Measurement-set controls now use one button for Start, Pause,
and Resume, plus a separate Stop button. Pause waits at clean measurement point
boundaries before the next position or sweep, while Stop cancels further points
and returns through the existing safe scanner return sequence.

The control pane layout is configurable from Settings without restarting the
app. ReHome and hight offset controls are hidden by default. Shutdown Program
now lives in the left menu under Settings.

Scanner connection failures no longer prevent unrelated app features from
loading. Missing or invalid COM ports now produce a clear warning
but let the app run. A short GRBL response timeout avoids
hanging on incorrect but valid COM ports.

Audio Setup now has an explicit microphone SPL calibration workflow: it shows a
held A-weighted mic reading, accepts a physical SPL meter reading, calculates and
saves the SPL offset only when Calibrate is pressed, and also allows manually
entering a known offset.

Live Capture audio meters are labelled from -60 dB to
0 dB, use RMS for the main bar, and show a slow-decay red peak marker. The
sine generator play button switches to a stop icon while the tone is playing.

--------
Added session-folder workflow to the HarmonicDrive UI. The top bar now lets the
user choose a Session Folder with the native folder picker, set a Save Name, and
save session state to <SaveName>_project.json. If no folder has been chosen, the
UI defaults to <default_project_dir>\HALS_Project, but only creates that folder
when the user saves, generates a grid, or starts a session.

Session files now store sweep setup data, SPL calibration if present, plus the
Grid Generator settings and waypoints needed to reopen or regenerate a grid.

Generated grids are saved into the active Session Folder as <SaveName>_grid.csv.

Full measurement output is routed to Session Folder\measurement_set,
Single measurements are routed separately to Session Folder\single_measurements.
The measurement position log stays at Session Folder\measurement_positions.csv,
and Scanner.log is saved under Session Folder\logs.

The Settings button now lives in the left sidebar and opens the
config editor. The config editor includes a default project directory and a
Restore Defaults action that restores default_config.ini

Added a dedicated Audio Setup pane and moved user-facing audio/sweep controls out
of the general config editor. The config editor remains the backend responsible
for validating, writing, and reloading config.ini, while its visible Audio tab now
only exposes the debug/test audio mode.

Audio Setup now includes:
- API-filtered device selectors
- sine tone generator for level setting
- SPL calibration field
- Test Sweep button
- All audio settings and sweep settings

Audio device selection is now more robust when device IDs change.
Config saves selected input/output device names as well as their device
IDs, uses the saved names to detect changes, and prompts the
user before updating the device IDs.

Test Sweep uses the active audio/sweep settings, including protection HPF and
sweep level, but returns the processed IR to Live Capture in memory rather than
writing permanent WAV, IR, or debug files.

Added real-time audio meters to Live Capture. Live Capture opens by default when
Audio Setup is opened so levels and Test Sweep results can be viewed while
adjusting the setup.

audio.py
--------------------------------

27/02/26
Refactor to follow Single Responsibility Principle (SRP).

RunSweep - Conductor that manages audio streams and execution of the other audio processing classes.

DSPUtils - A utility class containing pure mathematical functions such as Hann windowing, dB-to-linear conversion, and cross-correlation.

MarkerGenerator - Responsible for creating the Barker-13 sequence used to synchronize the timing of the recordings.

SweepGenerator - Handles the creation of the sweep signal and its corresponding inverse filter.

HarmonicInjector - A testing class that adds H2 or H3 harmonic distortion to the sweep signal to verify Farina distortion separation capability.

ProtectionFilter - Applies a high-pass filter (either Minimum or Linear Phase) to the playback signal to protect speaker drivers from damage.

AlignmentEngine - Manages temporal alignment of multiple sweeps by detecting the Barker markers and performs averaging to reduce noise.

DeconvolutionEngine - The core engine that performs deconvolution, applies spectral masking (DC and Nyquist minimum-phase filters), and separates the linear response from distortion.

27/02/26
Bug in audio_worker finally block:
Thread crash on full measurement set completion. Attempted to access non-existent app.loop attribute. Changed to capture the active event loop with asyncio.get_running_loop() in the UI thread and passing it to the worker.

28/02/26
Added MockInterfaceAudio class, enabled by config.ini. Simulates an audio interface so the sweep and IR generation pipeline can be verified without hardware. Simulation includes - Driver latency of 20ms, FIR anti-aliasing LPF based on CS4272 DAC specs, FIR filter group delay of 12/FS, DC blocking HPF based on C 10uF / R 10K ~15Hz 1st order.

28/02/26
Added a block in _matched_filter_detect to calculate the peak to sidelobe ratio of the barker marker correlation and flag a logger.warning() when the value is below 2.5 indicating potential alignment issues.

28/02/26
Added alignment_debug.npz export when debug_saves is enabled. Includes raw loopback, reference Barker-13, cross-correlation results, and quality metrics Peak-to-Sidelobe Ratio and match percent. Enables analysis of barker marker alignment quality using util analyze_marker_alignment.py. Implemented originally to inspect blurring caused by hardware DC blocking capacitors on audio interfaces.
